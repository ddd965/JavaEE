## 6. Mapper 接口与 XML 映射文件（详细说明）

MyBatis 的核心在于将 **Mapper 接口**（Java 方法）与 **XML 映射文件**（SQL 语句）绑定，实现数据访问。以下结合“电商订单管理系统”的实际需求，详细讲解：

- 基本单表 CRUD 操作  
- **一对一**（用户 ↔ 用户扩展信息）  
- **一对多**（用户 ↔ 订单）  
- **多对多**（订单 ↔ 商品，通过中间表）  
- 以及复杂查询（条件分页、动态 SQL）的完整实现。

---

### 6.1 Mapper 接口与 XML 的映射规则

| 要素 | 规则说明 |
|------|----------|
| 接口包路径 | `com.example.ecomorder.mapper` |
| XML 存放位置 | `src/main/resources/mapper/` |
| XML 命名空间 | 必须等于 Mapper 接口的全限定名，例如：`com.example.ecomorder.mapper.UserMapper` |
| 方法名与 SQL id | 必须一致 |
| 参数传递 | 单个参数直接用 `#{param}`；多个参数需用 `@Param("xxx")` 注解或在 XML 中使用 `arg0`，但推荐 `@Param` |

---

### 6.2 单表 CRUD 操作（以 ProductMapper 为例）

#### 6.2.1 Mapper 接口定义

```java
package com.example.ecomorder.mapper;

import com.example.ecomorder.entity.Product;
import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Param;
import java.math.BigDecimal;
import java.util.List;

@Mapper
public interface ProductMapper {

    // 插入商品（返回自增主键自动回填到 Product.id）
    int insert(Product product);

    // 根据主键更新
    int updateById(Product product);

    // 根据主键删除（物理删除）
    int deleteById(@Param("id") Long id);

    // 根据主键查询
    Product selectById(@Param("id") Long id);

    // 条件查询（名称模糊、分类、价格区间）用于分页
    List<Product> selectByCondition(@Param("name") String name,
                                    @Param("category") String category,
                                    @Param("minPrice") BigDecimal minPrice,
                                    @Param("offset") int offset,
                                    @Param("limit") int limit);

    // 条件查询总记录数（用于分页）
    long countByCondition(@Param("name") String name,
                          @Param("category") String category,
                          @Param("minPrice") BigDecimal minPrice);
}
```

#### 6.2.2 XML 映射文件（ProductMapper.xml）

```xml
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.example.ecomorder.mapper.ProductMapper">

    <!-- 结果映射：将数据库列名与实体属性对应（下划线转驼峰已开启，但显式写出更清晰） -->
    <resultMap id="BaseResultMap" type="com.example.ecomorder.entity.Product">
        <id column="id" property="id"/>
        <result column="name" property="name"/>
        <result column="price" property="price"/>
        <result column="stock" property="stock"/>
        <result column="category" property="category"/>
        <result column="status" property="status"/>
    </resultMap>

    <!-- 插入：使用自增主键 -->
    <insert id="insert" useGeneratedKeys="true" keyProperty="id">
        INSERT INTO product (name, price, stock, category, status)
        VALUES (#{name}, #{price}, #{stock}, #{category}, #{status})
    </insert>

    <!-- 更新 -->
    <update id="updateById">
        UPDATE product
        SET name = #{name},
            price = #{price},
            stock = #{stock},
            category = #{category},
            status = #{status}
        WHERE id = #{id}
    </update>

    <!-- 删除 -->
    <delete id="deleteById">
        DELETE FROM product WHERE id = #{id}
    </delete>

    <!-- 根据主键查询 -->
    <select id="selectById" resultMap="BaseResultMap">
        SELECT id, name, price, stock, category, status
        FROM product
        WHERE id = #{id}
    </select>

    <!-- 条件分页查询（动态 SQL） -->
    <select id="selectByCondition" resultMap="BaseResultMap">
        SELECT id, name, price, stock, category, status
        FROM product
        <where>
            <if test="name != null and name != ''">
                AND name LIKE CONCAT('%', #{name}, '%')
            </if>
            <if test="category != null and category != ''">
                AND category = #{category}
            </if>
            <if test="minPrice != null">
                AND price >= #{minPrice}
            </if>
        </where>
        ORDER BY id DESC
        LIMIT #{offset}, #{limit}
    </select>

    <!-- 条件统计 -->
    <select id="countByCondition" resultType="long">
        SELECT COUNT(*)
        FROM product
        <where>
            <if test="name != null and name != ''">
                AND name LIKE CONCAT('%', #{name}, '%')
            </if>
            <if test="category != null and category != ''">
                AND category = #{category}
            </if>
            <if test="minPrice != null">
                AND price >= #{minPrice}
            </if>
        </where>
    </select>

</mapper>
```

> **注意**：`useGeneratedKeys="true"` 和 `keyProperty="id"` 会令自增 id 自动回填到传入的 Product 对象中。

### 6.3 一对一关联查询（User ↔ UserProfile）

**业务场景**：查询用户基本信息的同时，获取其扩展信息（真实姓名、地址、积分）。

#### 6.3.1 VO 类（视图对象）

```java
package com.example.ecomorder.vo;

import lombok.Data;

@Data
public class UserWithProfileVO {
    private Long id;
    private String username;
    private String email;
    private String phone;
    private String realName;   // 来自 user_profile
    private String address;
    private Integer points;
}
```

#### 6.3.2 Mapper 接口

```java
public interface UserMapper {
    // 一对一查询：用户及其扩展信息
    UserWithProfileVO selectUserWithProfile(@Param("userId") Long userId);
}
```

#### 6.3.3 XML 映射（使用 resultType 直接映射）

```xml
<mapper namespace="com.example.ecomorder.mapper.UserMapper">

    <!-- 一对一查询（左连接，字段别名与 VO 属性对应） -->
    <select id="selectUserWithProfile" resultType="com.example.ecomorder.vo.UserWithProfileVO">
        SELECT u.id,
               u.username,
               u.email,
               u.phone,
               up.real_name   AS realName,
               up.address,
               up.points
        FROM user u
        LEFT JOIN user_profile up ON u.id = up.user_id
        WHERE u.id = #{userId}
    </select>

</mapper>
```

> **说明**：由于 VO 属性名（realName）与数据库列（real_name）不一致，使用 `AS` 别名映射。也可以定义 `resultMap` 使用 `association` 标签，但简单一对一直接用别名更简洁。

**如果需要使用 `association` 方式（更规范）**：

```xml
<resultMap id="UserWithProfileMap" type="com.example.ecomorder.vo.UserWithProfileVO">
    <id column="id" property="id"/>
    <result column="username" property="username"/>
    <result column="email" property="email"/>
    <result column="phone" property="phone"/>
    <!-- 使用 association 嵌套另一个对象 -->
    <association property="profile" javaType="com.example.ecomorder.entity.UserProfile">
        <result column="real_name" property="realName"/>
        <result column="address" property="address"/>
        <result column="points" property="points"/>
    </association>
</resultMap>

<select id="selectUserWithProfile" resultMap="UserWithProfileMap">
    SELECT u.id, u.username, u.email, u.phone,
           up.real_name, up.address, up.points
    FROM user u
    LEFT JOIN user_profile up ON u.id = up.user_id
    WHERE u.id = #{userId}
</select>
```

此时 VO 需要包含 `private UserProfile profile;` 属性。两种方式均可，推荐第一种（简单场景）。

### 6.4 一对多关联查询（User ↔ Order）

**业务场景**：查询一个用户及其下的所有订单。

#### 6.4.1 VO 类

```java
@Data
public class UserWithOrdersVO {
    private Long userId;
    private String username;
    private List<OrderVO> orders;   // 一对多，订单列表
}

@Data
public class OrderVO {
    private Long orderId;
    private String orderNo;
    private BigDecimal totalPrice;
    private Integer status;
    private Date createTime;
}
```

#### 6.4.2 Mapper 接口

```java
public interface UserMapper {
    UserWithOrdersVO selectUserWithOrders(@Param("userId") Long userId);
}
```

#### 6.4.3 XML 映射（使用 `resultMap` + `collection`）

```xml
<resultMap id="UserWithOrdersMap" type="com.example.ecomorder.vo.UserWithOrdersVO">
    <id column="user_id" property="userId"/>
    <result column="username" property="username"/>
    <!-- collection 表示一对多，ofType 指定集合中元素的类型 -->
    <collection property="orders" ofType="com.example.ecomorder.vo.OrderVO">
        <id column="order_id" property="orderId"/>
        <result column="order_no" property="orderNo"/>
        <result column="total_price" property="totalPrice"/>
        <result column="status" property="status"/>
        <result column="create_time" property="createTime"/>
    </collection>
</resultMap>

<select id="selectUserWithOrders" resultMap="UserWithOrdersMap">
    SELECT u.id          AS user_id,
           u.username,
           o.id          AS order_id,
           o.order_no,
           o.total_price,
           o.status,
           o.create_time
    FROM user u
    LEFT JOIN `order` o ON u.id = o.user_id
    WHERE u.id = #{userId}
</select>
```

**关键点**：
- 使用 `LEFT JOIN` 确保即使没有订单，用户信息也能返回（orders 为空集合）。
- `collection` 标签会遍历结果集，自动将同一用户的订单组装成 List。
- 主表（user）的列必须设置 `<id>` 标签，否则 MyBatis 无法区分对象边界。

### 6.5 多对多关联查询（Order ↔ Product 通过 order_item）

**业务场景**：查询一个订单，同时展示该订单包含的所有商品信息（含数量、小计）。

#### 6.5.1 VO 类

```java
@Data
public class OrderWithProductsVO {
    private Long orderId;
    private String orderNo;
    private BigDecimal totalPrice;
    private List<OrderProductVO> products;
}

@Data
public class OrderProductVO {
    private Long productId;
    private String productName;
    private Integer quantity;
    private BigDecimal subtotal;
}
```

#### 6.5.2 Mapper 接口

```java
public interface OrderMapper {
    OrderWithProductsVO selectOrderWithProducts(@Param("orderId") Long orderId);
}
```

#### 6.5.3 XML 映射（三表关联）

```xml
<resultMap id="OrderWithProductsMap" type="com.example.ecomorder.vo.OrderWithProductsVO">
    <id column="order_id" property="orderId"/>
    <result column="order_no" property="orderNo"/>
    <result column="total_price" property="totalPrice"/>
    <!-- 一对多：订单包含多个商品 -->
    <collection property="products" ofType="com.example.ecomorder.vo.OrderProductVO">
        <id column="product_id" property="productId"/>
        <result column="product_name" property="productName"/>
        <result column="quantity" property="quantity"/>
        <result column="subtotal" property="subtotal"/>
    </collection>
</resultMap>

<select id="selectOrderWithProducts" resultMap="OrderWithProductsMap">
    SELECT o.id            AS order_id,
           o.order_no,
           o.total_price,
           p.id            AS product_id,
           p.name          AS product_name,
           oi.quantity,
           oi.subtotal
    FROM `order` o
    LEFT JOIN order_item oi ON o.id = oi.order_id
    LEFT JOIN product p ON oi.product_id = p.id
    WHERE o.id = #{orderId}
</select>
```

**说明**：
- 多对多关系是通过中间表 `order_item` 拆解为两个一对多，本质上仍然是 MyBatis 的 `collection` 处理。
- 如果订单没有商品（异常情况），`products` 为空集合。

### 6.6 高级：一对多嵌套多对多（用户 -> 订单 -> 商品）

有时需要更深层嵌套，例如“查询用户，包含其每个订单的详细商品”。只需在 `collection` 中再嵌套 `collection`。

```xml
<resultMap id="UserWithOrdersAndProductsMap" type="com.example.ecomorder.vo.UserDeepVO">
    <id column="user_id" property="userId"/>
    <result column="username" property="username"/>
    <collection property="orders" ofType="com.example.ecomorder.vo.OrderDeepVO">
        <id column="order_id" property="orderId"/>
        <result column="order_no" property="orderNo"/>
        <!-- 订单里的商品集合 -->
        <collection property="products" ofType="com.example.ecomorder.vo.OrderProductVO">
            <id column="product_id" property="productId"/>
            <result column="product_name" property="productName"/>
            <result column="quantity" property="quantity"/>
        </collection>
    </collection>
</resultMap>
```

SQL 需要关联 user、order、order_item、product 四张表，MyBatis 会自动完成多层嵌套。

### 6.7 动态 SQL 与多条件分页（实际应用）

#### 6.7.1 复杂查询：订单列表（按用户、状态、时间范围）

**Mapper 接口**：

```java
List<OrderVO> selectOrderPage(@Param("userId") Long userId,
                              @Param("status") Integer status,
                              @Param("startTime") Date startTime,
                              @Param("endTime") Date endTime,
                              @Param("offset") int offset,
                              @Param("limit") int limit);
```

**XML 动态 SQL**：

```xml
<select id="selectOrderPage" resultType="com.example.ecomorder.vo.OrderVO">
    SELECT id, order_no, total_price, status, create_time
    FROM `order`
    <where>
        <if test="userId != null">
            AND user_id = #{userId}
        </if>
        <if test="status != null">
            AND status = #{status}
        </if>
        <if test="startTime != null">
            AND create_time >= #{startTime}
        </if>
        <if test="endTime != null">
            AND create_time &lt;= #{endTime}
        </if>
    </where>
    ORDER BY create_time DESC
    LIMIT #{offset}, #{limit}
</select>
```

### 6.8 注意事项与最佳实践

| 注意点 | 详细说明 |
|--------|----------|
| **XML 文件位置** | 必须放在 `mapper-locations` 配置的路径下（如 `classpath:mapper/*.xml`），且与 Mapper 接口包路径无关。 |
| **命名空间唯一性** | 每个 XML 的 `namespace` 必须与 Mapper 接口全类名一致，否则启动报错。 |
| **参数传递** | 多参数必须使用 `@Param("xxx")`，否则 MyBatis 会用 `param1, param2` 难以维护。 |
| **结果映射** | 单表简单查询可用 `resultType`；多表关联推荐使用 `resultMap`，尤其是涉及 `association` 或 `collection`。 |
| **N+1 查询问题** | 上述 `LEFT JOIN` 一次性查出所有数据，避免循环查询（N+1）。但若数据量极大，可考虑分步查询（使用 `select` 属性），但会增加 SQL 次数。 |
| **性能优化** | 对于一对多/多对多，尽量使用 `LEFT JOIN` 一次关联，同时注意字段不要过多（避免结果集膨胀）。 |
| **事务中的查询** | 若需要行锁，使用 `SELECT ... FOR UPDATE`，对应 Mapper 方法添加 `@Select` 注解或 XML 中写 `for update`。 |

### 6.9 完整示例：多表查询在 Service 中的调用

```java
@Service
public class ReportServiceImpl implements ReportService {
    @Autowired
    private UserMapper userMapper;
    @Autowired
    private OrderMapper orderMapper;

    @Override
    public UserWithOrdersVO getUserOrderSummary(Long userId) {
        // 直接调用 mapper 的一对多查询，返回结果已是 VO（组装好订单列表）
        return userMapper.selectUserWithOrders(userId);
    }

    @Override
    public OrderWithProductsVO getOrderDetail(Long orderId) {
        // 多对多查询
        return orderMapper.selectOrderWithProducts(orderId);
    }
}
```

**注意**：Service 层不应直接返回 Entity，而是返回 VO，因此 Mapper 的多表查询结果可以直接映射到 VO，符合分层要求。

### 6.10 验证实验要求（多表查询）

| 实验要求 | 对应实现 |
|----------|----------|
| 一对一查询 | `UserMapper.selectUserWithProfile` |
| 一对多查询 | `UserMapper.selectUserWithOrders` |
| 多对多查询 | `OrderMapper.selectOrderWithProducts` |
| 禁止仅单表查询 | 所有业务功能中至少使用上述一种多表关联查询（如订单详情页展示商品列表） |
