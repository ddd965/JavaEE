前端报错:
系统异常: Given that there is no defaultpassword encoderconigured, each password musthave a password encoding prefix. Please either preixthis password with "nop" orset a defaul password encoderin`DelegatingPasswordEncoder
问题描述:
密码编码器配置与数据库中存储的密码格式不匹配，登录的时候使用之前的账号密码登陆不上去，包括新注册的账户也没办法登录

这个错误,是 Spring Security 密码编码器配置与数据库中存储的密码格式不匹配导致的.前端看到的 580 错误,本质上是后端在验证登录密码时抛出的异常.

错误原因分析:
Spring Security 5.x引入了 DelegatingPasswordEncoder(委托式密码编码器)。它要求在存储密码时密码必须带有 编码方式前缀，格式为{编码ID}密码原文 。例如:
{noop}123456表示明文密码 123456
{bcrypt}$2a$10$...→表示 BCrypt 加密后的密文.
当系统调用 passwordEncoder.matches(用户输入的明文，数据库中的密码)验证登录时
1.DelegatingPasswordEncoder 会先解析数据库密码中的前缀(例如{noop})。
2.根据前缀找到对应的真实编码器(例如 NoopPasswordEncoder)来比对
3.如果数据库中的密码没有前缀，且你没有为 DelegatingPasswordEncoder 设置“默认编码器”，就会直接抛出你看到的这个异常。
所以，问题出在你的数据库里存储的用户密码没有编码前缀，而 Spring Security 又恰好配置了一个“没有默认匹配器"的 DelegatingPasswordEncoder。

为什么新注册用户也报错?
“注册”逻辑虽然调用了 BCrypt 加密，但没有在结果前拼接{bcrypt}。流程是这样的:
然后直接存1.注册时:你用了类似 new BcryptPasswordEncoder().encode("123456")，得到 $2a$18$...，入数据库。
2.登录时:Spring Security的 DaoAuthenticationProvider 会通过 DelegatingPasswordEncoder 来验证密码。
3.DelegatingPasswordEncoder 看到数据库里的密码是 $2a$1e$...，开头没有{编码ID}，又因为你没给它配置“默认编码器”，于是直接抛出异常。
所以，哪怕注册流程中有加密，只要没加前缀，就一定会在这里报错
